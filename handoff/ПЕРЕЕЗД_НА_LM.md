Записано 4 сентября 2026 на машине `ulorew-BRN` перед переездом на `lm`.
Адресат — тот, кто продолжит работу на lm (человек или следующая сессия).

Схема сменилась: **STM32 из тракта убран**, теперь ESP32 + SimpleFOCMini +
RCTimer GBM 4108-130T, энкодер AS5048A по SPI. Поэтому половина накопленного —
рабочий инструмент, а половина — описание железа, которого больше нет. Ниже
разделено явно, потому что смешать их дороже, чем не иметь вовсе.

## 1. Первое действие: свести репозитории

**Истории НЕ разошлись** — это удача, и её легко потерять.

* lm стоит на `88b8c35` (22 августа).
* BRN стоит на `986fd3e`, это **36 коммитов поверх** головы lm.
* Встречных коммитов у lm нет: `git rev-list --count HEAD..88b8c35` = 0.

Значит слияние — обычная перемотка, без разрешения конфликтов.

### Что мешает перемотке

На lm есть незакоммиченное:

| путь | что это | судьба |
|---|---|---|
| `stm/build.sh` (изменён) | правка `read -r ответ` → `ANSWER` | **выбросить**: коммит `a82e5ea` чинит то же самое, но с комментарием и с запасным путём заливки через ST-LINK |
| `esp/as5048a_probe/`, `esp/foc_bench/`, `esp/foc_closed_probe/`, `esp/foc_mini_probe/`, `esp/psram_check/` | новая работа по SPI и FOC | **закоммитить**, но без `build/` |
| `esp/build.sh` | сборщик скетчей ESP32 | закоммитить |
| `docs/spi_encoder/README.md` | разбор перехода на SPI | закоммитить |
| `tools/stand/enc_plot.py`, `tools/stand/foc_matrix.py` | новые инструменты | закоммитить |

**Осторожно с размером:** `esp/` весит 222 МБ, и это почти целиком каталоги
`build/` (по 42–47 МБ на скетч). В `.gitignore` их нет. Перед коммитом добавить
`esp/*/build/`, иначе репозиторий распухнет необратимо.

### Порядок

```bash
# на lm
cd ~/Projects/SurfTracker
git checkout -- stm/build.sh                 # правка дублирует a82e5ea
printf 'esp/*/build/\n' >> .gitignore
git add .gitignore esp docs/spi_encoder tools/stand/enc_plot.py tools/stand/foc_matrix.py
git commit -m "ESP32 + SimpleFOCMini + 4108: SPI-энкодер, разомкнутый и замкнутый пробники, стенд матрицы"

# затем принять 36 коммитов с BRN (push на checked-out ветку git запретит,
# поэтому через промежуточную ветку)
#   на BRN:  git push lm master:refs/heads/from-brn
#   на lm:   git merge from-brn
```

**Запасного пути через GitHub НЕТ.** `origin` (`Ulorew/SurfTracker`) стоит на
`8bacf38` и отстал от обеих машин: он предок и головы lm, и моей — на 263
коммита. Тридцати шести коммитов серии там нет, и вообще ничего после августа.
Если BRN станет недоступен раньше слияния, работа останется только на нём.

Отсюда же вывод: **отправить в `origin` стоит сразу после слияния** — сейчас
единственная полная копия истории лежит на одной машине.

## 2. Новый стенд: что уже доказано

Не переизмерять — это снято на железе 4 сентября и записано в
`docs/spi_encoder/README.md` и шапках скетчей.

### Распиновка (ESP32 DOIT DevKit 38 пинов, правый ряд)

| сигнал | GPIO | | сигнал | GPIO |
|---|---|---|---|---|
| CLK | 18 | | IN1 | 17 |
| MISO | 19 | | IN2 | 16 |
| MOSI | **21** | | IN3 | 4 |
| CS | **5** | | EN | 22 |
| | | | светодиод | 2 |

Три тонкости, каждая уже стоила отладки:

* **MOSI на 21, не на штатном 23.** Тогда `SPI.begin(18, 19, 21, 5)` обязан
  быть с аргументами, иначе драйвер уйдёт на 23 и датчик не ответит при
  правильных проводах.
* **Режим SPI 1** (CPOL=0, CPHA=1), 1 МГц. Режим 0 даёт сдвиг на бит и «почти
  правдоподобные» углы — тихо неверные числа, а не заметный мусор.
* **GPIO 16 и 17 свободны** — это ПРОВЕРЕНО замером (`esp/psram_check` дал
  0 байт PSRAM, модуль WROOM), а не предположено. У WROVER они заняты.

Брать нельзя: 0 (strapping, DRV8313 тянет вниз → плата уйдёт в загрузчик),
6–11 (флеш), 15 (гасит лог загрузки).

### Датчик

| | SPI, 14 бит | прежний PWM + `micros()` |
|---|---|---|
| шаг квантования | **0.0220°** | 0.3930° |
| СКО на покое | **0.036°** | 0.234° |

Шаг совпал с теоретическим 360/16384 до четвёртого знака.

**Не сравнивать это с 0.046° из `reports/МОТОР.md`.** Там другой тракт —
аппаратный захват TIM2 на 170 МГц, а здесь `micros()` на ESP32. Числа не
сопоставимы, и сведение их в одну таблицу даст ложный вывод.

### Мотор

**11 пар полюсов подтверждены на новом моторе** (шапка
`esp/foc_closed_probe`): датчик видит вал, масштаб скорости 1.003 и 0.998.
Знак датчика **обратен** направлению поля.

`zero_electric_angle` гуляет между запусками 3.778…3.826 — поэтому матрица
коэффициентов гоняется одним прогоном без перезаливок, иначе разброс
выравнивания попадёт в результат как разброс коэффициентов.

## 4. Правила владельца — действуют и на новом стенде

Взяты из переписки, не выводятся из кода.

* **Напряжение.** При долгой работе подряд — потолок 2 В. 2.5 В до 10 минут,
  3 В до минуты. Временное правило серии, пока нет пирометра: прогоны на
  U_база ≥ 2 В не длиннее 3 минут подряд, пауза до «рука держит спокойно»
  (~45 °C).
* **Перед каждой партией прогонов писать явно** «вал не трогать» или
  «придержите вал». Владелец: *«Срываю каждый запуск. Пиши явно с просьбой это
  делать, а то мне непонятно, надо ли.»*
* **Действия с телефоном** (чехол, питание, перезапуск, место, освещение) —
  только явной просьбой и с подтверждением. Не предполагать состояние.
* **Понятные ошибки чинить без спроса.** Непонятные или требующие выбора —
  оставлять и спрашивать.
* **Коммитить на значимых изменениях**, чтобы не было неразберихи.
* Имена файлов — латиницей.

## 5. Классы ошибок, которые повторялись

Не абстракции: каждый пункт стоил часов и найден в этом проекте.

**«Величина выглядит измеренной, а её нет.»** Напечатанное число, которое для
этого прогона не измерялось. Случаи: `dump()` печатал `n_samp` вместо реально
заполненных отсчётов и выдавал старый буфер за данные; вывод «зуд падает со
скоростью» стоял на записи, где сторож оборвал прогон через 1.41 с и почти всё
окно занимал СТОЯЩИЙ мотор.

**Мёртвая ветвь.** Правило реализовано в N местах, чинится в том, которое не
исполняется. Случаи: детектор срыва жил только в `blocks_step` и не работал в
замкнутом контуре, а заголовок печатал `срыв=0`; `guard()` звался в цикле
записи, но не в цикле установления — три секунды рампы шли без защиты, а поля
`вибр_уст` печатались нулями и читались как «тихо».

**Окно замера должно совпадать с режимом.** Полосы считались на окне 0–9 с, а
мотор разгонялся первые 3.3 с и вставал на 15.5-й. Треть окна была рампой.
На честном окне 3.5–15.3 с **выбор конфигурации перевернулся**. Правило:
посекундный разбор ДО расчёта, окно печатать рядом с числом.

**Мост между шкалами меряется явно.** Новый источник меток времени — сперва
смещение к существующим часам. На новом стенде это уже сработало: хостовые
метки дали скорость вала 11 546 320 °/с, потому что строки приходят пачками из
буфера USB. Метку ставит плата, до чтения датчика, а не `printf`.

**Сперва контроль, потом теория.** Отсутствующую фазу мотора искали часами,
объясняя симптомы теорией управления. Достаточно было прогнать тест с заведомо
равномерным вращением. Владелец прямо говорил, что равномерности не наблюдает.

**Одномерная настройка двух коэффициентов.** P и I масштабировались
одновременно, и это не было сказано. После разделения: P в одиночку
дестабилизирует, I монотонно улучшает, а составной оптимум был вдвое хуже.

## 6. Незакрытые хвосты

### По новому стенду (lm)

1. **Матрица прогнана, свод не сделан.** `runs/foc_matrix_2026-09-04_2338/` —
   45 ячеек (P×I×скорость), файлы `P0p2_I10_v0p1.txt` и т.д. Сводного
   отчёта в каталоге нет. Считать через `tools/stand/foc_matrix.py`,
   спектр — в двух шкалах (в герцах и в циклах на оборот), иначе резонанс
   и зубцы не различить.
2. Замкнутый контур снят четырьмя записями `foc_closed_*_2026-09-04.csv` —
   разобраны ли они, по репозиторию не видно.
3. `zero_electric_angle` не прибит константой; решение отложено осознанно —
   прибивать имеет смысл проверенное число.

### По старому контуру (перенести в долги, если он ещё нужен)

Полный список — `reports/STAGE0_REPORT.md`, раздел 5. Кратко: перелёт на
0.05 рад/с (ход/команда 1.05 против критерия 0.99–1.01) блокирует тег
`motor-v1`; паспорт стенда не собран; аномалия `#НАПРАВЛЕНИЕ` (синхронизм
4.224, один выброс на 46 замеров) не объяснена.

### По связке с телефоном

`handoff/ВЫЕЗД_КОНФИГ.md` — версия промежуточная. Семь шагов из девяти
закрыты. Открыты два, и оба упирались в одно: **ESP32-мост не спарен с
телефоном.** Мост при этом исправен — скан с ноутбука видел его в эфире как
`38:18:2B:30:7D:86 SurfTracker-Link`. В списке спаренных на телефоне 14
устройств, моста среди них нет.

**Внимание при переезде:** заливка любого скетча на ESP32 перезаписывает мост
`bt_link`, а вместе с ним канал телефон → мотор (об этом предупреждает сам
`esp/build.sh`). Если мост и контур теперь живут на ОДНОЙ плате — это
конфликт, который надо решить осознанно, а не обнаружить в поле.

## 8. Что я бы сделал первым на lm

По убыванию отдачи:

1. **Свести репозитории** (раздел 1) — пока истории не разошлись, это пять
   минут. После первого коммита на lm поверх старой головы будет уже слияние.

таблицы. Мотор другой; совпадение числа пар полюсов делает соблазн опаснее,
а не безопаснее.
