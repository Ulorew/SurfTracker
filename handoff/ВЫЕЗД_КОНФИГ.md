## Тепловой режим телефона — правило берега

Снято из `reports/ТЕЛЕФОН.md` (тепловые прогоны, три конфигурации), железо сегодня не
трогалось.

**Сессия ≤ 10 минут.** Причина: на 11–15-й минуте батарея доходит до 46 °C, и через минуту
после этого скорость падает **втрое разом** — частота анализа проседает с 3.0 до 2.0 Гц.
Худший случай (без чехла, на USB) — обвал на 12-й минуте.

Что важно и расходится с интуицией:

* **Запись при этом НЕ падает.** 26.1 к/с по файлу, максимальный разрыв 101–207 мс. Падает
  анализ. То есть видео останется, а ведение испортится — и по видео это будет незаметно.
* **Зарядка ускоряет нагрев** (0.82 против 0.73 °C/мин при том же потолке 46 °C). Держать
  телефон на повербанке во время ведения — вредно. Повербанк — для платы и моста.
* **Приборам телефона верить нельзя:** `getCurrentThermalStatus` во всех прогонах показывал
  0 (троттлинга нет) при падении скорости втрое, а `getThermalHeadroom` в прогоне БЕЗ
  обвала был выше, чем в прогонах с обвалом. Ориентироваться **по часам**, а не по API.
* Цена чехла — ноль (3 мс по p50 при разбросе между минутами 10 мс).

## НЕ РАБОТАЕТ: Bluetooth-мост — ESP32 НЕ СПАРЕН

`java.io.IOException: read failed, socket might closed or timeout, read ret: -1`.

**Причина установлена:** на телефоне 14 спаренных устройств (часы Amazfit, наушники,
колонки, чужие телефоны), и MAC моста `38:18:2B:30:7D:86` среди них **отсутствует**.
Неспаренное устройство даёт ровно этот симптом.

Исключено по ходу разбора:

| версия | результат |
|---|---|
| погашенный экран | причина отказа **камеры**, но не моста |
| питание ESP32 от ноутбучного USB | перезапитан с мотором — без изменений |
| поиск сохранённого модуля | тот же отказ |
| MAC `XX:XX:XX:XX:XX:XX` (единственный похожий из спаренных) | тот же отказ |
| MAC `38:18:2B:30:7D:86` (документированный) | тот же отказ — устройство не спарено |

**Действие:** спарить ESP32 с телефоном заново через настройки Bluetooth. После этого
повторить прогон без флага `dry` — и связка закроется целиком.
