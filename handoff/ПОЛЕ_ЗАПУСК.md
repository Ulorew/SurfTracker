# Запуск в поле. Пошагово

Составлено 22 августа. Приоритет владельца: **запустить хоть как-то — от
батареи, с трекингом и записью.** Плавность и качество — вторым заходом.
Замкнутого контура нет и не требуется.

Связь на месте плохая: всё нужное должно быть уже на носителе.

---

## 0. Что обязано быть с собой

| | зачем |
|---|---|
| ноутбук | заливка прошивки и запуск прогона; без него запуск с телефона возможен, но вслепую |
| **кабель USB к ST-LINK платы** | на плате лежит НЕ боевая прошивка, перезалить больше нечем |
| кабель USB к телефону, **с данными** | заливка APK и модели; зарядные кабели без данных не годятся |
| плата + мотор + энкодер, мост ESP32 | |
| **внешние 12 В** | без них нет ESP и Bluetooth. Телефон плату по OTG НЕ тянет: шина сбрасывается через 3–13 с |
| архив `surftracker_FULL_*.tar.gz` | только в нём APK и боевой двоичник прошивки |

Телефон работает **от своей батареи весь прогон**: зарядка в режиме хоста
невозможна. Тепловые числа (полка 45 °C) сняты на заряжающемся телефоне и
потому **занижены** — в поле будет горячее.

## 1. Прошивка платы — ПЕРВЫМ ДЕЛОМ

**На плате сейчас `elzero_g431`.** Он при каждом включении питания подаёт 2 В
и крутит вал: сначала электрический оборот вперёд-назад (32.7° механических),
потом пять рывков по 5–15°. Ничего не сломается, но людей и хрупкое от вала
убрать.

```bash
cd ~/Projects/SurfTracker
OCD=$(ls ~/.arduino15/packages/STMicroelectronics/tools/xpack-openocd/*/bin/openocd | head -1)
SCR=$(dirname $(dirname "$OCD"))/openocd/scripts
"$OCD" -s "$SCR" -f interface/stlink.cfg -f target/stm32g4x.cfg \
  -c "program stm/phone_link/build/phone_link.ino.elf verify reset exit"
```

Ждать **`** Verified OK **`**. Если openocd ругается на права USB — поставить
правило и переткнуть кабель:

```bash
sudo cp ~/.arduino15/packages/STMicroelectronics/tools/xpack-openocd/*/openocd/contrib/60-openocd.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

> **НЕ БРАТЬ** `stm/backup/phone_link_21.08/phone_link.ino.bin` — это сборка
> под SimpleFOC 2.3.5, а на плате 2.4.0. Файл `stm/ВОЗВРАТ.md` до сих пор
> ошибочно указывает на него. Правильный файл — `stm/phone_link/build/`.

Пересобрать прошивку в поле **нельзя**: SimpleFOC не лежит в репозитории, она
тянется из интернета.

## 2. Телефон

```bash
. ~/Android/env.sh
adb devices                 # должно показать устройство и слово device
```

Пусто — проверить: кабель с данными, отладка по USB включена, на экране
телефона подтверждён запрос авторизации.

**Приложение:**

```bash
adb install -r android/camfps/build/com.surftracker.camfps.apk
```

**Модель — шаг ручной и нигде больше не записанный.** Приложение ищет файл в
своём каталоге; если приложение переустанавливали или чистили данные, там
пусто, и прогон упадёт на загрузке модели уже на воде.

```bash
D=/storage/emulated/0/Android/data/com.surftracker.camfps/files
adb shell mkdir -p $D
adb push models/phone/person_w8a32.tflite $D/
adb shell ls -l $D
```

Проверить, что файл на месте и размер 3 039 349 байт.

## 3. Какую модель выбрать

В приложении: **Настройки → Модель → Файл модели.**

- `person_w8a32.tflite` — **сток COCO, детектор людей.** Это то, что стоит по
  умолчанию. Для проверки на людях годится и рекомендуется на первый выезд.
- модель по виндсерфам (`night_legacy_s3_best.pt`) на телефон **никогда не
  экспортировалась**. Если экспорт успели сделать до выезда — файл будет
  рядом, и его имя надо вписать в то же поле.

Проверить, что лежит на телефоне: `adb shell ls $D`.

## 4. Прогон

Предполёт **блокирующий и его нельзя проглядеть** — так сделано намеренно,
после трёх потерянных прогонов.

```bash
tools/link/run_track.sh --ez sync true --ei seconds 480 \
    --ez video true --es quality 1080 --ei fps 24 --es tag поле
```

Дальше **на телефоне кнопка СТАРТ**.

Готовые сценарии — `tools/link/runs_plan.sh`:

| сценарий | что делает |
|---|---|
| `полный` | 8 минут, запись, возврат в исходное — проба изделия целиком |
| `потери` | уходить из кадра и возвращаться: проверка возврата после потери |
| `толчок` | стоять неподвижно, стенд сам отклоняется — замер плавности |

**Запись — FullHD, а не 4K, и это решение по замерам.** Рабочий режим зумлен
до 2.125, а там 4K пуст геометрически: с матрицы берётся полоса не шире 1920
настоящих пикселей. Платой за 4K были бы четверть такта (196 → 252 мс) и
21 пункт удержания цели (98% → 77%).

**Прогон без мотора** (проверить только зрение и запись, стенд не нужен):

```bash
tools/link/run_track.sh --ez dry true --ei seconds 120 --ez video true
```

## 5. Если что-то не пошло

| симптом | вероятная причина |
|---|---|
| предполёт «не пройден» | снято 12 В; на плате диагностический скетч; телефон отвалился от adb |
| плата отвечает, но вал стоит | поле включается только после первой НЕнулевой уставки — так задумано, чтобы сброс не дёргал камеру |
| «канал молчит» | версии прошивки и хоста разошлись. У боевой прошивки кадр диагностики 27 байт; у старых 24 |
| прогон падает на старте | нет файла модели в каталоге приложения, см. §2 |
| вал дёргается при включении | на плате остался `elzero_g431`, см. §1 |

Телефон в прогоне **сам говорит, что делать** — сценарии написаны под голос.

## 6. Чего от этой сборки ждать НЕ надо

- **Дальний галс не проверен ни разу.** Это главный полевой риск, и он не про
  мотор, а про то, увидит ли модель мелкую цель.
- **Замкнутого контура нет.** Скорость держится разомкнуто, точность 0.987–1.003
  от команды — этого достаточно; плавность на малых скоростях не оптимизирована.
- **Скорости 0.20–0.30 и 0.45–0.50 рад/с** — зона раскачки подвеса. Если ход
  будет заметно дёрганым, дело скорее всего в ней.
- **Калибровки камеры не существует** — ни интринсик, ни дисторсии.
