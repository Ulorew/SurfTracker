# Выравнивание датчика: снято 22 августа 2026

*Запись относится к прежней цепи на STM32 (B-G431B-ESC1); пути `stm/…`, `esp/bt_link`
и `docs/pwm_reform` доступны под тегом `stm-era`.*

## Зачем это нужно

`initFOC()` крутит вал при КАЖДОМ включении: ищет направление датчика
(электрический оборот вперёд и назад) и электрический ноль (удержание поля).
На стенде терпимо, на мачте с камерой — нет.

SimpleFOC 2.4.0 пропускает оба шага, если заданы **оба** поля:

```
FOCMotor.cpp:861   if (sensor_direction == Direction::UNKNOWN) { ...крутит... }
FOCMotor.cpp:908   if (!_isset(zero_electric_angle))           { ...держит... }
```

Одного мало: второй шаг всё равно подаст напряжение.

## Результат

```
static const Direction DIR_ISR = Direction::CW;
static const float     ZEA_ISR = 4.55650f;    // тракт micros(), PB8
static const Direction DIR_CAP = Direction::CW;
static const float     ZEA_CAP = 4.64678f;    // аппаратный захват, PA15
```

Условия: 2.0 В, пять повторов со сбросом поля между попытками, оба тракта
сняты за ОДНУ установку ротора.

## Две самопроверки, и обе сошлись

- **сдвиг за электрический оборот 0.56871 рад** при 2π/11 = 0.57120;
- **оценка пар полюсов 11.048** при известных 11.

Это та проверка, которую библиотека делает внутри ветки калибровки
(`FOCMotor.cpp:897`) и которую мы теряем НАВСЕГДА, зашив константы. Поэтому
она вынесена в печать отдельно.

- **направление у трактов совпало** (оба CW). Расхождение означало бы, что
  один из них отображает угол зеркально, и это чинят, а не зашивают.

## Почему константы РАЗНЫЕ у двух трактов

`zero_electric_angle` считается от `getMechanicalAngle()` конкретного
датчика, а тракты отображают импульс в угол по-разному: мост измерен и он не
тождественный (наклон 362.1–362.8 град на единицу скважности, мёртвый участок
кадра около процента). Разница вышла 0.0903 рад электрических = 0.47°
механических — того же порядка, что смещение моста.

## ЛОВУШКА В ТАБЛИЦЕ ПОВТОРОВ

```
#  mech_isr   mech_cap
0  4.41262    4.42068
1  4.41262    4.42098
2  4.41262    4.42045
3  4.41262    4.42085
4  4.41262    4.42117
```

Боевой тракт дал **буквально одно и то же число** во всех пяти попытках, и
кучность вышла 1.0000. Прочитать это как «идеальная повторяемость» —
ошибка: квант тракта 0.39258°, а настоящий разброс, который показал тракт
захвата, **0.041°**, то есть в девять раз мельче кванта. Старый тракт его не
видит вовсе.

Это ровно та семья ошибок, которую проект ловит весь месяц: величина
выглядит измеренной и превосходной, а на деле мера грубее измеряемого.
Кучность боевого тракта здесь не характеристика вала — она характеристика
слепоты прибора.

## Чего этот замер НЕ говорит

- **Стабильность между включениями платы не проверена.** Все пять попыток
  сделаны за один прогон, без снятия питания. Проверять — повторным замером
  в другой день.
- **Температурная зависимость не проверена** вовсе.
- Замер сделан при 2.0 В. При другом напряжении ротор доезжает иначе, и
  константа может сместиться.

## Как перемерить

```bash
./stm/build.sh elzero_g431           # собрать
# залить openocd с верификацией, снять вывод с /dev/ttyACM0 на 115200,
# затем ОБЯЗАТЕЛЬНО вернуть боевую прошивку phone_link
```

Скетч печатает и ничего не зашивает: числа переносит человек.

**Вал при этом дёргается на 5–15°, и это норма.** Сначала электрический
оборот (при 11 парах полюсов — 32.7° механических, вперёд и назад), потом
пять сбросов поля с возвратом ротора в одну точку. Плавного вращения тут не
бывает по устройству замера.
