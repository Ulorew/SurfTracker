# Как продолжить без стенда

## Что работает офлайн, без железа

Все проверки. Прогнать разом:

```bash
cd ~/Projects/SurfTracker
./tools/windowing/proto_stand_check/check.sh          # протокол: C++ против питона
.venv/bin/python tools/windowing/diag_metrics_check/check.py
./tools/windowing/capture_sensor_check/check.sh       # класс датчика + мутации
```

Все три должны сказать, что сошлось. Если нет — начинать надо с этого, а не с
новой работы.

Пересчитать любой замер из `runs/`:

```bash
.venv/bin/python tools/link/diag_metrics.py runs/v2_spin.csv
.venv/bin/python tools/link/smoothness.py runs/ladder_load.csv
```

Собрать любую прошивку без заливки:

```bash
./stm/build.sh phone_link          # без флага прошивки — только компиляция
./stm/build.sh looprate_g431
./stm/build.sh elzero_g431
```

## Что требует стенда

- заливка (`./stm/build.sh <имя> --прошить`, либо openocd с верификацией);
- любой новый замер;
- проверка стабильности выравнивания при снятии питания.

**Перед заливкой снимать снимок флеша.** Он уже спас один раз: показал, что на
плате SimpleFOC 2.4.0, тогда как собирали под 2.3.5.

```bash
OCD=$(ls ~/.arduino15/packages/STMicroelectronics/tools/xpack-openocd/*/bin/openocd | head -1)
SCR=$(dirname $(dirname "$OCD"))/openocd/scripts
"$OCD" -s "$SCR" -f interface/stlink.cfg -f target/stm32g4x.cfg \
  -c "init; reset halt; dump_image снимок.bin 0x08000000 0x20000; reset run; shutdown"
```

## Правила работы со стендом, выведенные опытом

- **Напряжение:** 2.0 В при долгой работе подряд, 2.5 В до десяти минут,
  3 В до минуты.
- **Скорость:** держаться подальше от 0.20–0.30 и 0.45–0.50 рад/с — там
  задокументированная раскачка, возбуждаемая заходом СНИЗУ. Стенд ходит на 0.15.
- **Версии прошивки и хоста меняются парой.** Несовпадение даёт не мусор, а
  МОЛЧАНИЕ канала. В `stand.py` есть предполётная сверка по длине кадра.
- **Любое действие с железом — по явной просьбе к владельцу**, состояние
  стенда не предполагать.

## Как не повторить сегодняшние ошибки

Три штуки поймано за день, и все одной семьи — «величина выглядит измеренной,
а её нет»:

1. **Метрика плавности завышала в 39 раз.** Числа выглядели правдоподобно.
   Поймала подложка с ЗАЛОЖЕННЫМ ответом, а не глаз. После первой правки
   осталось ровное завышение ×1.225 — одной проверкой его от калибровки не
   отличить, отличили четырьмя точками с разными амплитудами.
   **Правило: новая метрика проверяется на данных с известным ответом, и не в
   одной точке.**

2. **Класс датчика браковал свежие чтения и принимал устаревшие.** Доля брака
   равнялась (1 − скважность), то есть зависела от угла. Вскрылось на железе:
   отказ при скважности 0.156. Правило существовало в двух местах и разъехалось.
   **Правило: одно правило — одно место. Живая ветка та, что исполняется.**

3. **«Кучность 1.0000» и «наклон × размах = 360»** — обе выглядели как
   проверки и обе ничего не проверяли. Первая насыщена, вторая инвариантна к
   той самой ошибке, которую должна ловить.
   **Правило: проверку надо испытывать порчей. Не ломается — она декоративна.**

## Пакет

Отдельно от репозитория ничего не нужно: всё в git. Если нужен архив только
существенного:

```bash
tar czf surftracker_handoff.tar.gz \
  handoff/ docs/journal/ tools/link/ tools/windowing/ stm/ runs/*.csv \
  --exclude='stm/*/build' --exclude='__pycache__'
```
