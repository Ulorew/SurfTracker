# Запуск в поле. Пошагово

Переписано 24 сентября под новую цепь: **телефон → Bluetooth → ESP32 →
мотор 3506.** STM32, ST-LINK, openocd и `elzero_g431` из цепи ушли — всё,
что про них, в прежней редакции (git log этого файла).

Связь на месте плохая: всё нужное должно быть уже на носителе.

---

## 0. Что обязано быть с собой

| | зачем |
|---|---|
| ноутбук | предполёт, запуск прогона, выгрузка и сводка |
| **кабель USB к ESP32 (с данными)** | перезалить прошивку и читать `STATE`; других путей к плате нет |
| кабель USB к телефону, **с данными** | заливка APK и модели, если Wi-Fi-отладка не поднимется |
| плата ESP32 + SimpleFOCMini + мотор 3506 + AS5048A | |
| **питание 12 В** на драйвер | без него ни мотора, ни платы |
| телефон в люльке, заряжен | работает от своей батареи весь прогон |

## 1. Плата: на ней должна быть `field_link`

Проверка — предполёт (§4) делает её сам. Перезалить, если он не проходит:

```bash
cd ~/Projects/SurfTracker
esp/build.sh field_link --прошить        # на вопрос ответить: да
```

**При каждом включении питания вал коротко дёргается** — это калибровка
датчика (initFOC), так задумано. После неё поле снято и включается только
первым кадром с телефона. Светодиод платы: горит — телефон на связи;
медленно мигает — ждёт телефон; часто — отказ датчика (нужен сброс питанием).

Настройки мотора вшиты: `P=4 I=5 Tf=0.12 COGK=+1`, потолок 2 В. `Tf=0.12`
— не опечатка: при 0.01 люлька вибрирует в 140 раз сильнее фона и кадр
теряет резкость в 5-19 раз (замер 24.09, docs/foc_tuning/ИТОГИ_24.09.md).

Посмотреть состояние с ноутбука (**открытие порта перезагружает плату**):
`STATE` в любом терминале на 115200.

## 2. Телефон

```bash
. ~/Android/env.sh
adb devices                 # должно показать устройство и слово device
```

Пусто — проверить: кабель с данными, отладка по USB включена, на экране
телефона подтверждён запрос авторизации.

**Приложение:**

```bash
adb install -r android/camfps/build/com.surftracker.camfps.apk
```

**Модель — шаг ручной и нигде больше не записанный.** Приложение ищет файл в
своём каталоге; если приложение переустанавливали или чистили данные, там
пусто, и прогон упадёт на загрузке модели уже на воде.

```bash
D=/storage/emulated/0/Android/data/com.surftracker.camfps/files
adb shell mkdir -p $D
adb push models/phone/surf_w8a32.tflite   $D/     # боевая, по виндсерфам
adb push models/phone/person_w8a32.tflite $D/     # сток COCO, для тестов на людях
adb shell ls -l $D
```

Размеры: `surf_w8a32.tflite` 2 997 445 Б, `person_w8a32.tflite` 3 039 349 Б.

## 3. Какую модель выбрать

В приложении: **Настройки → Модель → Файл модели.**

- **`surf_w8a32.tflite` — БОЕВАЯ, обученная по виндсерфам. Ставить её для
  работы по воде.**
- `person_w8a32.tflite` — сток COCO, детектор людей. Стоит по умолчанию в
  приложении. Годится только для проверки на людях у берега.

> **ПОПРАВКА К ПЕРВОЙ РЕДАКЦИИ.** Здесь стояло «модель по виндсерфам на
> телефон никогда не экспортировалась». Неверно: экспорт был сделан 5 августа,
> но его результат существовал в единственном экземпляре — на самом телефоне.
> Забран в `models/phone/surf_w8a32.tflite`.
>
> **Разница измерена, и она решающая.** На 147 кадрах, 649 целей: полнота
> person **0.601** против surf **0.986**. На дальнем галсе (цель 32–120 px)
> порога уверенности достигают **8.8%** целей у person против **97.3%** у
> surf. То есть со стоковой моделью дальнего сёрфера камера просто не увидит.
> Выехать с `person` — значит выехать без трекинга по воде.

Проверить, что лежит на телефоне: `adb shell ls $D`.

## 4. Прогон

```bash
cd ~/Projects/SurfTracker
export ANDROID_SERIAL=<адрес телефона из adb devices>   # см. §5
tools/link/run_track.sh --ez defaults true --ef zoom 2.125 --ef focus 0 \
    --es model surf_w8a32.tflite \
    --ez sync true --ei seconds 480 \
    --ez video true --es quality 1080 --ei fps 24 --es tag поле
```

`run_track.sh` сначала гонит **блокирующий предполёт**: 20 нулевых уставок
по Bluetooth с ноутбука, ответов должно быть не меньше 15, энкодер жив.
Нулевая уставка вал не трогает. Адрес платы (`38:18:2B:30:7D:86`)
подставляется сам — телефон с ESP32 не сопряжён, и искать её по имени
бесполезно.

Флаги, без которых прогон пропадает:

| флаг | без него |
|---|---|
| `--ez defaults true` | берутся настройки, сохранённые на телефоне с прошлого раза |
| `--ef zoom 2.125` | парус 4.4 м на 150 м даёт 38 px вместо 81 |
| `--ef focus 0` | **НОВОЕ.** Автофокус на стенде гулял между 20 см и 1-2 м; на воде цель в 50-100 м, фокус — бесконечность |
| `--es model surf_w8a32.tflite` | работает сток COCO, дальнего сёрфера не видно, см. §3 |

Дальше **на телефоне кнопка СТАРТ**.

**Знак** (`DIR=-1` в прошивке) подтверждён живым слежением 24.09: камера
шла за человеком 90 с, на цели 99.5%. Если после перепайки мотора или
драйвера камера начнёт **уходить от цели** — знак сменился: перезалить с
`DIR=+1` (строка `static const int DIR` в `esp/field_link/field_link.ino`).

**Прогон без мотора** (только зрение и запись):

```bash
tools/link/run_track.sh --ez dry true --ei seconds 120 --ez video true --ef focus 0
```

## 5. После сессии: выгрузка и статистика

```bash
tools/link/pull_sessions.sh 2609              # метка дня: ГГММ
tools/link/pull_sessions.sh 2609 --без-видео  # быстро, только логи
```

Кладёт в `runs/field_<метка>/` и сразу печатает сводку по каждой сессии и
итогом: доля времени на цели, число и длительность потерь, ошибка наведения
p50/p95, флаги мотора (сторож, срыв, энкодер), такт телефона. Таблица — в
`сводка.csv` там же. Пустая колонка лога печатается как «НЕТ ДАННЫХ», а не
как ноль.

## 6. Если что-то не пошло

| симптом | вероятная причина |
|---|---|
| `adb: more than one device` | телефон виден дважды (mdns и явно): `export ANDROID_SERIAL=...` |
| предполёт: BT не поднялся | снято 12 В; Bluetooth ноутбука выключен; на плате стендовый `foc_bench` |
| предполёт: энкодер молчит | отошёл провод датчика (SPI: 14/27/26/25) |
| плата отвечает, но вал стоит | поле включается только первым кадром — так задумано |
| камера уходит от цели | знак, см. §4 |
| светодиод часто мигает | отказ датчика: угол замер при ненулевой команде; сброс питанием |
| прогон падает на старте | нет файла модели в каталоге приложения, см. §2 |

## 7. Чего от этой сборки ждать НЕ надо

- **Ветер.** Позиционного контура в плате нет: после толчка вал
  возвращается медленно, а держит камеру только интеграл скорости. Это
  главный механический риск в поле; лог покажет его как рост ошибки
  наведения при ведении.
- **Ложная цель.** В сухом прогоне по пустой комнате трекер 13% времени
  «вёл» несуществующую цель и выдавал уставки до 0.37 рад/с. С мотором
  камера поедет за ней.
- **Дальний галс не проверен ни разу** — увидит ли модель мелкую цель.
- **Разворот через ноль** (сёрфер поворачивает) на стенде не мерился.
- **Калибровки камеры нет** — ни интринсик, ни дисторсии.
