# Протокол телефон ↔ STM32, версия 1

Тикет «замыкание контура телефон → мотор», ступень 1. Зафиксировано **до
кода**: прототип переживёт себя, а спецификация останется.

Железо: Redmi Note 14 Pro 5G ←USB-OTG→ Nucleo-F411RE + SimpleFOCShield,
BGM4108 с энкодером AS5048A. Энкодер — **только лог и диагностика**, контур
скоростной open-loop (вывод стендовых тестов).

Транспорт: USB CDC-ACM через ST-LINK VCP, **115200 8N1**, порядок байт
**little-endian**, float32 IEEE 754.

---

## Кадр телефон → STM32 (7 байт, 25 Гц)

| смещение | размер | поле | смысл |
|---|---|---|---|
| 0 | 1 | `0xA5` | магик |
| 1 | 1 | `seq` | счётчик, растёт по модулю 256 |
| 2 | 4 | `ω_cmd` | float32, **рад/с**, знак = направление |
| 6 | 1 | `CRC8` | по байтам 0..5 включительно |

## Кадр STM32 → телефон (8 байт, на каждый принятый валидный кадр)

| смещение | размер | поле | смысл |
|---|---|---|---|
| 0 | 1 | `0xA5` | магик |
| 1 | 1 | `seq` | **эхо** принятого seq |
| 2 | 4 | `θ_enc` | float32, **рад**, показание энкодера |
| 6 | 1 | `статус` | биты, см. ниже |
| 7 | 1 | `CRC8` | по байтам 0..6 включительно |

`θ_enc` обязателен в каждом ответе. Это будущий лог «кадр → угол»: без него
пост-кроп и любая привязка изображения к механике слепы.

### Биты статуса

| бит | значение |
|---|---|
| 0 | сторожевой сработал (команда обнулена по таймауту) |
| 1 | энкодер жив (данные свежие и в допуске) |
| 2 | ограничение скорости активно (запрошено больше, чем разрешено) |
| 3 | предыдущий принятый кадр отброшен по CRC |
| 4–7 | резерв, обязаны быть 0 |

Бит 3 добавлен к перечню тикета намеренно: без него телефон не отличит
«кадр не дошёл» от «кадр дошёл битым», а это разные неисправности — первая
про кабель и питание, вторая про скорость порта и наводки.

---

## CRC8

Полином **0x07** (CRC-8/ATM), начальное значение **0x00**, без отражения
входа и выхода, без финального XOR. Считается по всем предшествующим байтам
кадра, включая магик.

```c
uint8_t crc8(const uint8_t *d, size_t n) {
    uint8_t c = 0x00;
    while (n--) {
        c ^= *d++;
        for (int i = 0; i < 8; i++)
            c = (c & 0x80) ? (uint8_t)((c << 1) ^ 0x07) : (uint8_t)(c << 1);
    }
    return c;
}
```

### Контрольные векторы

Обе стороны обязаны воспроизвести их побайтово до первого включения мотора.
Это дешевле, чем ловить рассогласование CRC на живом контуре.

**Запрос:**

| seq | ω_cmd | байты | CRC |
|---|---|---|---|
| 0 | 0.0 | `A5 00 00 00 00 00` | `5A` |
| 1 | 1.5 | `A5 01 00 00 C0 3F` | `68` |
| 255 | −2.25 | `A5 FF 00 00 10 C0` | `7A` |
| 42 | 0.017453292 (1°/с) | `A5 2A 35 FA 8E 3C` | `3B` |

**Ответ:**

| seq | θ_enc | статус | байты | CRC |
|---|---|---|---|---|
| 0 | 0.0 | `0x02` | `A5 00 00 00 00 00 02` | `8F` |
| 1 | 3.14159265 | `0x02` | `A5 01 DB 0F 49 40 02` | `41` |
| 255 | −1.0 | `0x03` | `A5 FF 00 00 80 BF 03` | `A0` |
| 42 | 0.5 | `0x06` | `A5 2A 00 00 00 3F 06` | `8F` |

## Поведение при ошибках

* **CRC не сошёлся** — кадр считается непринятым: команда НЕ обновляется,
  ответ НЕ отправляется, сторожевой продолжает отсчёт. Следующий валидный
  ответ несёт бит 3.
* **Магик не на месте** — байт выбрасывается, приём продолжается со
  следующего. Ресинхронизация по магику, а не по длине: при потере байта
  выравнивание по длине залипает навсегда.
* **До первого валидного кадра** `ω_cmd = 0`. Мотор не двигается, пока
  телефон не сказал ни слова.

## Сторожевой

Нет валидного кадра **300 мс** → останов **по трапеции с ограничением
рывка**, не обрывом. Обрыв команды на вращающемся моторе — это удар по
механике и скачок тока; трапеция снимает и то, и другое.

Числа ограничения (максимальное угловое ускорение, рывок) задаются прошивкой
и обязаны попадать в снимок конфигурации каждого лога (`РЕГЛАМЕНТ.md §3`) —
иначе разбор «почему остановился так» невозможен задним числом.

Восстановление: первый же валидный кадр снимает бит 0 и возвращает
управление. Отдельной команды сброса нет — лишнее состояние, которое можно
забыть снять.

## Бюджет линии

| | |
|---|---|
| один байт при 115200 8N1 | 86.8 мкс |
| 7 байт запроса + 8 ответа | **1.30 мс** |
| период 25 Гц | 40 мс |
| занятость линии | **3.3%** |

Запас тридцатикратный. Скорость порта — не то место, где стоит искать
задержку; если jitter периода окажется большим, причина будет в планировщике
телефона или в USB-хосте, а не в 115200.

## Лог обмена (телефон)

Одна строка на кадр, csv, заголовок в первой строке:

```
t_phone_ns,seq,w_cmd,theta_enc,status,rtt_ms,ok
```

`ok` = 0 при потере ответа (таймаут), 1 при валидном ответе, 2 при битом
CRC ответа. Рядом — снимок конфигурации по §3: версия протокола, скорость
порта, период, коммит, идентификатор устройства.

## Версионирование

Правило тикета: при первом же изменении формата версия ставится **в первый
байт после магика**.

**Оговорка, которую надо решить до того, как понадобится.** В версии 1 этот
байт занят `seq`, поэтому по проводу v1 и v2 станут неразличимы: приёмник не
сможет понять, что перед ним, не зная заранее. Различимость на проводе стоит
одного байта сейчас или отладочного дня потом.

Предложение на момент первого изменения: **менять магик** (`0xA5` → `0xA6`),
а версию класть следующим байтом. Тогда старый приёмник просто не узнает
кадр и промолчит, вместо того чтобы принять чужой формат за свой и поехать.
Решение за владельцем; в v1 формат остаётся ровно таким, как задан тикетом.
