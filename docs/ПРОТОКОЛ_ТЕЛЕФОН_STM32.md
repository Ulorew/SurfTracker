# Протокол телефон ↔ STM32, версия 2

Транспорт: Bluetooth SPP через мост ESP32 (либо USB CDC-ACM напрямую —
протокол байтовый и о транспорте ничего не знает). **115200 8N1**,
little-endian, float32 IEEE 754. Радианы, рад/с, рад/с².

Железо: Redmi Note 14 Pro 5G → BT → ESP32 → UART → Nucleo-F411RE +
SimpleFOCShield, BGM4108 с AS5048A.

---

## 0. Принцип, из которого следует всё остальное

**Пакет — это уставка, а не команда.** Вал ведёт рампа контроллера
(ограничение ускорения), работающая на своей килогерцовой частоте; любой
скачок уставки превращается в наклон рампы. Канал может дёргаться — вал не
может.

Отсюда же следует, что накопительной рассинхронизации нет **по построению**:
уставка абсолютная (скорость, а не приращение), любой применённый кадр
полностью замещает состояние, ошибки не суммируются.

---

## 1. Транспорт и кадрирование

SPP/RFCOMM — **надёжный поток с сохранением порядка**: кадры не теряются и не
переставляются, они **опаздывают**, иногда пачками после замирания радио.
Два следствия:

* защита нужна от **устаревших** уставок, а не от потерянных;
* это байтовый поток без границ — кадрирование своё.

Кадр фиксированной длины. Ресинхронизация: искать магик, проверить CRC всего
кадра; не сошлось — сдвиг на один байт и снова. Выравнивание по длине без
магика залипает навсегда при потере одного байта.

**Магики разные по направлениям** (0xA5 и 0x5A): при склейке или зацикливании
это сразу видно, а приёмник не может принять собственный кадр за чужой.

## 2. Кадры

### Телефон → STM: уставка, 11 байт, 10 Гц

| смещение | размер | поле | смысл |
|---|---|---|---|
| 0 | 1 | `0xA5` | магик |
| 1 | 1 | версия/seq | бит 7 — версия (0 для v2), биты 0–6 — seq по модулю 128 |
| 2 | 4 | `ω` | уставка скорости, рад/с |
| 6 | 4 | `ω̇` | наклон уставки, рад/с² (0 допустим — вырождение в v1) |
| 10 | 1 | `CRC8` | по байтам 0..9 |

### STM → телефон: телеметрия, 12 байт, на каждый принятый кадр

| смещение | размер | поле | смысл |
|---|---|---|---|
| 0 | 1 | `0x5A` | магик |
| 1 | 1 | seq | эхо принятого |
| 2 | 4 | `θ_enc` | угол вала, рад, **после медианного фильтра** (см. §5) |
| 6 | 4 | `ω_ramp` | **выход рампы = исполняемая команда, НЕ измерение** |
| 10 | 1 | статус | биты, см. ниже |
| 11 | 1 | `CRC8` | по байтам 0..10 |

**`ω_ramp` названа так намеренно.** В разомкнутом контуре это команда после
всех ограничений, а не скорость вала. Прежнее имя «ω_факт» приглашало читать
её как измерение, и тогда механический срыв стал бы невидим ровно в тот
момент, когда он случается. Настоящая скорость вала в протоколе не
передаётся: продифференцировать `θ_enc` при квантовании 0.394° на 10 Гц даёт
около 4°/с шума, то есть больше полезного сигнала. Вместо этого — детектор
срыва по интегралу, §6.

### Биты статуса

| бит | значение |
|---|---|
| 0 | watchdog сработал |
| 1 | потолок экстраполяции достигнут |
| 2 | рампа насыщена (исполнение отстаёт от уставки) |
| 3 | энкодер жив |
| 4 | уставка ограничена пределом (2.0 или 6.0 рад/с) |
| 5 | **расхождение интеграла** — подозрение на срыв (§6) |
| 6–7 | счётчик CRC-ошибок по модулю 4 |

**Свободных битов НЕ ОСТАЛОСЬ.** Заняты все восемь: 0–3 механика и
watchdog, 4 ограничение, 5 расхождение интеграла, 6–7 счётчик. Резервировать
нечего, и это записано явно, чтобы «свободный бит» не был придуман задним
числом.

**Правило на случай девятого флага.** Занять «свободный» бит нельзя — его
нет. Варианты только два: отобрать биты у счётчика CRC (он сжимается до
одного бита-флага без потери назначения) либо расширить кадр с поднятием
версии. Молча переиспользовать существующий бит запрещено: неопределённый или
двусмысленный бит через месяц занимают два разных куска кода под разные
нужды, и это выглядит как мигающий статус, а не как ошибка.

> **Разрешение конфликта в задании.** Задание v2 отводило под счётчик
> CRC-ошибок биты 4–7 (модуль 16) и одновременно требовало битов «ограничение
> активно» и «расхождение интеграла». Восемь бит на всё не хватает. Счётчик
> сокращён до **двух бит (модуль 4)**: его назначение — показать, что порча
> идёт и с какой частотой, а для этого достаточно видеть изменение на соседних
> кадрах при 10 Гц. Диагностические биты приоритетнее точного счёта: они
> сообщают о состоянии механики, счётчик — о состоянии канала, который и так
> виден по потерям в логе телефона.

## 3. CRC8

**CRC-8/MAXIM** (Dallas): полином 0x31 отражённый (0x8C при счёте с младшего
бита), начальное значение 0x00, отражение входа и выхода, без финального XOR.
Считается по всем предшествующим байтам кадра, включая магик.

```c
uint8_t crc8(const uint8_t *d, size_t n) {
    uint8_t c = 0x00;
    while (n--) {
        c ^= *d++;
        for (int i = 0; i < 8; i++)
            c = (c & 1) ? (uint8_t)((c >> 1) ^ 0x8C) : (uint8_t)(c >> 1);
    }
    return c;
}
```

**ВНИМАНИЕ: это ДРУГОЙ CRC, чем в v1** (там был CRC-8/ATM, полином 0x07).
Векторы v1 непригодны, использовать их — гарантированно разойтись.

Самопроверка реализации: `CRC("123456789") = 0xA1`.

### Контрольные векторы

**Оба конца обязаны пройти их юнит-тестом до первого живого обмена.**
Расхождение таблиц CRC на живом контуре выглядит как «канал молчит» и стоит
вечера отладки не там, где причина.

Уставка (11 байт):

| случай | байты |
|---|---|
| нулевая, seq=0 | `A5 00 00 00 00 00 00 00 00 00 17` |
| ω=1.0, ω̇=0.1, seq=1 | `A5 01 00 00 80 3F CD CC CC 3D 44` |
| ω=−2.0, ω̇=0.5, seq=127 | `A5 7F 00 00 00 C0 00 00 00 3F CD` |

Телеметрия (12 байт):

| случай | байты |
|---|---|
| штатная (энкодер жив), seq=0 | `5A 00 00 00 00 00 00 00 00 00 08 D5` |
| θ=0.1745329, ω_ramp=0.5, статус 0x2A, seq=42 | `5A 2A C1 B8 32 3E 00 00 00 3F 2A 43` |
| watchdog+кламп, θ=−1.0, статус 0x19, seq=127 | `5A 7F 00 00 80 BF 00 00 00 00 19 21` |

## 4. Приёмник STM: правила применения уставки

1. **Свежесть.** Кадр применяется, только если seq новее последнего
   применённого — по модулю 128, окно вперёд 1..64. Пачка после замирания:
   применяется только последний кадр пачки, остальные молча считаются
   устаревшими.
2. **Уставка между кадрами:** `ω_уст(t) = ω_пакета + ω̇_пакета·(t − t_приёма)`,
   где t — часы STM. Абсолютного времени в протоколе нет намеренно: ошибка
   против честной синхронизации равна ω̇ × задержка доставки ≈ тысячные доли
   °/с, строить часы ради этого нельзя.
3. **Потолок экстраполяции 150 мс.** ω̇ интегрируется не дольше 150 мс от
   момента приёма, дальше уставка держится константой (бит 1). Иначе обрыв
   связи с ненулевым ω̇ разгоняет мотор.
4. **Watchdog 300 мс.** Нет валидного кадра дольше — уставка становится нулём,
   и вал приходит к нулю **через ту же рампу**: не обрыв тока, не свободный
   выбег. Бит 0.
5. **Возобновление.** Любой валидный кадр снимает watchdog. При seq вне окна
   (перезапуск телефона) кадр принимается безусловно — рампа сгладит.
6. **Рампа — последний рубеж, активна всегда.** Предел ускорения
   **1.0 рад/с²** (≈57°/с²): на порядок выше боевой динамики цели (≈0.1 рад/с²
   на 20 м), скачок уставки в 10°/с растягивается на ~0.2 с. Оценка для
   rolling shutter: за время считывания кадра ~30 мс изменение скорости
   ≤1.7°/с, изгиб вертикалей ничтожен.

### Пределы скорости — два уровня

| уровень | значение | где |
|---|---|---|
| предел уставки | **2.0 рад/с** (≈115°/с) | **и в мосте, и в прошивке** |
| аппаратный предел | **6.0 рад/с** | только прошивка |

Дублирование в мосте и прошивке намеренное: аппаратный предел страхует от
бага моста. Уставка выше предела клампится с битом 4.

Прежний предел 20 рад/с **удалён**, а не закомментирован.

Следствие: худший случай останова по watchdog при рампе 1.0 рад/с² — **2 с** с
предельной уставки и доли секунды с боевых 0.1–0.3 рад/с. Отдельное аварийное
замедление не вводится: усложнение без выигрыша.

## 5. Медианный фильтр телеметрии

`θ_enc` перед записью в кадр телеметрии проходит **медиану по 5 отсчётам**.

**Только в телеметрию.** В управлении `θ_enc` не участвует вовсе: боевой
контур разомкнут по скорости, положение замыкает камера на 3 Гц с допуском
±15°.

Основание — замер на неподвижном вале (`reports/КОНТУР_ТЕЛЕФОН_МОТОР.md`):
шаг квантования PWM-датчика **0.3939°** (913 отсчётов на оборот, а не 16384
как у чипа по SPI), размах дрожания **4.73°**, дрейф ноль. Дрожание
высокочастотное — джиттер прерывания, — а логу «кадр→угол» нужен угол на
момент кадра, и запаздывание фильтра ему безразлично.

Медиана берётся по 5 отсчётам **с интервалом 20 мс** (окно 100 мс).
Интервал обязателен: первая редакция набирала отсчёты каждой итерацией цикла,
а он идёт на килогерце — медиана покрывала 5 мс и не давала ничего.

Ожидание, записанное до реализации: остаточное дрожание **≤1°**.
**ПРОВЕРЕНО И ВЫПОЛНЕНО.** Сырое и фильтрованное сняты подряд на одном и том
же неподвижном вале (два прогона по 600 кадров, вал между ними не трогали):

| | сырой | медиана |
|---|---|---|
| p95 \|θ − медиана окна\| | 1.575° | **0.394°** |
| максимум | 2.363° | 0.788° |
| размах | 4.333° | 1.182° |
| уровней квантования | 12 | 4 |

Сравнивать РАЗНЫЕ прогоны для этого нельзя: положение вала и распределение
по уровням квантования у них разные, и вывод получается про выборку, а не
про фильтр. Первая попытка сравнения так и ошиблась — показала, что фильтр
«хуже сырого», хотя сравнивались два несопоставимых замера.

Для такой сверки в прошивке оставлен флаг `TELEMETRY_RAW_THETA`.

## 6. Детектор срыва по интегралу

В разомкнутом контуре механический срыв невидим: команда исполняется «на
бумаге» независимо от того, крутится ли вал. Единственная доступная
диагностика — сравнение **углов**, а не скоростей.

Прошивка накапливает на скользящем окне 1 с:

```
Δ = θ_enc − ∫ ω_ramp · dt
```

`|Δ| > 3°` → бит 5. Квантование 0.394° на секундном окне усредняется, а шум
дифференцирования обойдён тем, что сравниваются углы.

**Сброс интеграла** при срабатывании watchdog и при возобновлении связи.

**Детектор доказан на настоящей неисправности.** Первый же запуск мотора дал
вал, не следующий за командой (причина оказалась в прошивке — см. ниже), и
бит поднялся на **89 кадрах из 99**. После починки на том же режиме —
**0 из 50**. Без него телеметрия показывала бы «команда 0.2 рад/с» и
выглядела бы здоровой.

Тест: придержать вал рукой — бит обязан подняться за ≤1.5 с.
Мутация «интеграл не сбрасывается при возобновлении» обязана ронять тест
ложного срабатывания после watchdog.

## 7. Телефонная сторона

`ω` и `ω̇` берутся **из состояний фильтра** (они гладкие), а не численным
дифференцированием команд. Для alpha-beta:

```
ω  = K·(θ_цели − θ_камеры) + θ̇_цели
ω̇ = K·(θ̇_цели − ω_текущая_уставка)      (θ̈ цели в фильтре нет — ноль)
```

Лог на каждый эхо-кадр: `t_отпр, t_приёма, seq, θ_enc, ω_ramp, статус`.

Привязка угла к телефонным часам: `t = (t_отпр + t_приёма)/2`,
неопределённость ≈ RTT/2 ≈ 20 мс → ошибка угла ≤0.35° при 17°/с, внутри ±15°
с запасом на порядок. **Это и есть лог «кадр→угол», вторых часов не нужно.**

## 8. Перечисление событий → поведение

Доказательство анти-рывка перечислением. Каждая строка — отдельный тест
стресс-инжекции с видео вала.

| событие | что происходит | скачок на валу |
|---|---|---|
| штатный кадр, канал ровный | малый шаг уставки, рампа отрабатывает | нет |
| кадр опоздал (40 → 116 мс) | уставка чуть дольше едет по ω̇, новый кадр — малый шаг | нет |
| замирание радио 150–300 мс | потолок: держим ω константой | нет |
| пачка из 3 кадров после замирания | применён только последний, два устаревших отброшены | нет |
| обрыв > 300 мс | watchdog: рампа к нулю | нет, плавный стоп |
| восстановление после обрыва | кадр принят, рампа разгоняет к уставке | нет |
| битые байты, рассинхрон потока | CRC режет, ресинк по магику, уставка прежняя | нет |
| перезапуск телефона (seq скачет) | принять безусловно, рампа сгладит | нет |
| ω̇ задан ошибочно большим | потолок 150 мс ограничивает интеграл, рампа — исполнение | ограничен |

## 9. Мутации, обязательные к падению тестов

| мутация | какой тест обязан упасть |
|---|---|
| свежесть выключена (применяется каждый кадр пачки) | тест пачки |
| потолок экстраполяции снят | тест обрыва с ω̇ ≠ 0 |
| рампа обойдена | тест скачка уставки |
| интеграл срыва не сбрасывается при возобновлении | тест ложного срабатывания после watchdog |

## Вне рамок

Синхронизация абсолютных часов, сжатие и батчинг телеметрии, шифрование,
второй канал на ноутбук, переход датчика на SPI (отложен владельцем: в плате
выведен один сигнальный провод, перепайка — отдельная работа с железом).
